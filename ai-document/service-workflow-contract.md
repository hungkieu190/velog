- Existing RecordRepository/WriteCoordinator/WriteUnit own authoritative private service envelopes, exact versions, state projections, attributed UTC audit and rollback. Direct repository mutations must enforce the same domain rules through schema write guards; UI checks are not authority.
- Incomplete draft: active existing vehicle required; optional date/reading/type/cost; plain notes <=10000 characters. Creator is authenticated actor, never posted technician ID. Draft visible/editable by creator or manager only. Manager means existing mf_velog_correct_services capability; type administration uses mf_velog_manage_settings. Unknown reading/cost are empty tuples, distinct from zero.
- Finalize requires active vehicle, active private current customer, date <=site-local today, reading and active service type. Snapshot private customer ID/name and type ID/label under the write lock. No phone/email/user-account customer substitute. Finalized service vehicle/creator/customer snapshot are immutable; subsequent vehicle-owner changes do not reattribute history. Manager correction may amend date/reading/type/notes/cost with a nonempty reason <=1000 chars. Type changes snapshot the selected active type; renaming/deactivating a type never rewrites prior snapshots. No finalized-to-draft or delete transition.
- Cost uses Money's original/minor-unit/currency/scale/catalog tuple; new cost input uses system currency, historical costs retain their currency and are never automatically converted or summed. Distance input and display use system unit with the approved no-drift preservation policy; context nonce binds unit/currency for stale Settings detection.
- Type taxonomy is private, no native admin/REST/public terms or delete controls. Explicit versioned active/inactive records and audit accompany taxonomy rows. Changes use the same pinned coordinator lock as finalization; no WP term writes/reconnectable $wpdb inside transactions. No automatic default terms or live seed. Reads and uniqueness checks fail closed on duplicate/corrupt authoritative data.
- Chronology orders finalized services by service_date then service ID descending; baseline follows same-day finalized services. Compare affected reading against both chronological neighbours, including baseline. A manager reason permits an attributed decrease exception; technician decrease never does. Baseline edits use the same vehicle-specific neighbour guard, replacing the global finalized-service lock only for validated workflow records. Unsupported/corrupt history still fails closed.
- Current reading is an authoritative computed read model, derived from finalized history plus baseline; no separately persisted cache can lag a committed service. Resolve under the existing coordinator lock for consistent related snapshots. Backdating never automatically replaces a newer reading. A correction moving the latest service earlier recomputes from remaining records. No asynchronous jobs or eventual consistency. Catalog is bounded at 1000 types and current-reading validation at 10000 finalized services per vehicle; exceeding either limit fails closed with storage_unavailable. Bounded history safety guard fails closed rather than truncating silently; full G-08 performance remains separately unverified.

## HTTP/view contract

Native classic WordPress forms and tables, no new framework. Services menu allows operational staff; Service Types menu manager/admin only. Services list is bounded 50 rows with state/vehicle filters and stable IDs. Own drafts plus finalized services are visible to technician; manager sees all. Never expose other authors' drafts through query, ID route, direct repository read, audit or HTML. Display name-only historical customer/type/creator information. Archive vehicle blocks new draft/draft edits/finalization but preserves authorized finalized reads and reasoned manager corrections. Current reading is shown on the selected vehicle's service screen.

All mutations POST only, per-action/object nonce, exact scalar/UUID/positive ID/version, capability and authoritative guard. Invalid detail does not render a create fallback. No bulk finalization/deletion. Finalize has an explicit button and explanatory irreversible-state notice; finalized edits have an explicit correction action/reason. Missing Settings blocks forms safely. Fixed notices cover forbidden/missing/invalid/stale/chronology/active-relation/storage failures without SQL disclosure. All output escaped, labels associated, native keyboard controls, horizontal table scroll region. Tester owns responsive/RTL/screen-reader observations.
