## Findings and correction blueprint — revision 5, readiness PASS

**D1-F-013 / P1 / AC1, AC4 — Bounded query contract is broken.** `RecordRepository.php:146-201` selects and unserializes every matching post/meta row before applying policy and slicing a page of 50. One request therefore loads the full history of a type, including large audit envelopes, regardless of page number. It also silently skips malformed/duplicate authoritative rows rather than failing closed. Design a bounded, stable SQL candidate scan with allowlisted predicates and a separate authorized count plan that does not load all payloads into PHP at once. Prove page continuity, exact authorized totals, duplicate/malformed rejection and bounded memory/query plans at meaningful scale. Keep object policy before returning data.

**D1-F-014 / P1 / AC2 — Unique-key check fails open and mishandles composite rules.** `RecordRepository.php:867-913` checks each field of a unique rule separately, so a composite `(A,B)` conflicts when only A matches; `query_direct() === false` is treated as no match, allowing a create/save after a failed uniqueness query. Check the complete registered tuple atomically under the coordinator lock, return `storage_unavailable` on SQL failure, and reject duplicate/corrupt projection rows. Add positive controls for distinct composite tuples and negative controls for exact collision and injected query failure.

**D1-F-015 / P1 / AC2, AC4 — Transaction failure classification remains unsafe.** `WriteCoordinator.php:281-290` returns retryable `conflict` for lock timeout/deadlock even when the attempted ROLLBACK failed. Lines 331-339 return `indeterminate` on lost COMMIT acknowledgement but provide no reconciliation implementation; the contract requires a new-lock request-ID/authoritative-row reconciliation before retry. Cache invalidation and timeout restoration in `finally` are not checked for failure. Return `indeterminate` whenever rollback/connection/cache state is uncertain, implement the bounded reconciliation path, and test each failure with a pinned-connection fault, not a mock success response.

**D1-F-016 / P1 / AC2–AC4 — Required failure matrix remains incomplete.** The submitted V2 tests one multi-record rollback after two creates, but not failure after each individual write. V4 tests lock timeout and an intentional callback abort; it does not inject failed SQL, failed COMMIT, disconnect before/after COMMIT, deadlock or restart reconciliation. V3 validates retention after uninstall file execution but does not cover semantic regional values or taxonomy terms. Run the pinned contract's negative controls on both disposable WordPress versions, capture raw database before/after state and worker exits, and mark any unsupported case NOT VERIFIED instead of presenting V1–V5 as fully passed.

**D1-F-017 / P2 / test ownership and cleanup — Runner can affect other processes and claim cleanup without proof.** `run.php:38` chooses a predictable PID-derived directory; lines 387-400 read a PID file, call `kill` and `pkill -f`, then run `rm -rf` without verifying process identity, command exits or absence of remaining owned resources. `pkill -f` also matches the runner's own shell command and logged exit 15. Replace this with atomically allocated per-run ownership, recorded child PID/start identity, bounded graceful shutdown and explicit absence checks before deleting only the owned directory. A cleanup failure must make the suite nonzero. Keep reusable fixtures and evidence; report scratch files per the updated workflow rule.

**D1-F-018 / P1 / AC1, AC4 — Sensitive-field policy is not bound for future customer schemas.** `RecordSchema.php:255-264` registers the production customer schema with empty `contact_fields`, while `RecordRepository.php:1379-1403` redacts only fields listed there. Once a later domain task registers phone/email, an already-sealed production registry cannot add those keys or their redaction policy. Make field-policy registration extensible through trusted bootstrap before sealing or fail closed for unclassified customer fields; prove that every readable customer field and audit snapshot has a declared exposure policy before its validator is enabled. Do not add unapproved domain validators in DATA-001.
