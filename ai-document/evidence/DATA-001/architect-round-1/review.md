## Findings and correction blueprint — revision 4, readiness PASS

**D1-F-007 / P1 / AC1–AC4 — Fixture failure is reported as success.** The fixture `v*_assert()` helpers declare `global $failures`, while WP-CLI `eval-file` executes the file in a local scope and the final `if ( empty( $failures ) )` reads that local variable. In `v2_concurrency.php:346-351`, the summary prints `ALL V2 ASSERTIONS PASS` immediately after multiple `FAIL` lines; the same pattern occurs in V1, V3 and V4. Fix assertion state so the helper and final check use the same storage. Require the runner to reject any failed assertion, `ERROR:` output or missing success marker regardless of process exit. Add a deliberate failing control proving a nonzero suite exit. Re-run both WP versions and retain full per-case outputs.

**D1-F-008 / P1 / AC2, AC4 — Transaction detection fails open and causes database errors.** `WriteCoordinator.php:133-141` queries `information_schema.INNODB_TRX`, which requires `PROCESS` in the submitted WP 6.4.3 fixture, then accepts `null` as no active transaction. The log shows repeated access-denied errors during writes. Use a supported, privilege-safe check or fail closed when the state cannot be established; verify exact connection state before mutation. Cover a genuine pre-existing transaction and restricted DB account. Re-run lock timeout with measured wait, expected conflict code and state proof.

**D1-F-009 / P1 / AC1, AC4 — Customer contact data remains in audit snapshots.** `RecordRepository.php:1290-1314` removes sensitive keys from `fields` for an actor without `mf_velog_read_customer_contacts`, but returns the complete `audit` array. `AuditEntry` stores before/after field snapshots, so a technician can read phone/email/address from audit even when current fields are redacted. Apply the same field-level policy to audit content, or return an authorized audit projection. Add get/query tests with contact data in create and save history.

**D1-F-010 / P1 / AC1, AC2 — Query authorization and pagination remain inconsistent.** `RecordRepository.php:121-124` still rejects an actor without the write capability before considering `read_capability`. Lines 151-169 paginate all posts before applying state and object policy, then lines 243-246 replace `total` with only the current page's visible count. Authorized rows beyond a filtered page can never fill that page; totals vary with page and may disclose raw counts when no rows were rejected. Apply the declared read capability and authorized filtering before limit/offset; return a stable authorized total and pages. Verify mixed-visibility and multi-page cases.

**D1-F-011 / P1 / AC1–AC4 — Domain rules were introduced outside the approved boundary and the submitted tests do not prove them.** `RecordSchema.php:255-325` registers `name`, contact fields, VIN uniqueness, `vehicle_visible` and reminder notes as production schemas despite the DATA-001 contract reserving entity-specific fields and identifiers for later tasks. It also defaults missing service visibility to true at line 307. Several V2/V3/V4 creates fail in WP 6.7.2; V5 records zero successes. Keep production registration limited to the generic contract or return a documented architecture gap requiring a scope decision. Do not claim VIN, contacts or service relation semantics as accepted DATA-001 behavior. Rebuild fixtures around approved trusted test schemas and make every required create assert success before dependent checks.

**D1-F-012 / P1 / AC2, AC4 — Multi-record and failure evidence is still incomplete.** `v2_concurrency.php:174-204` calls `RecordRepository::create()` from inside `WriteCoordinator::run()`, which the coordinator deliberately rejects as a nested unit; this does not exercise two mutations within one trusted unit. V4 proves neither a five-second lock timeout nor cache behavior after an injected rollback on WP 6.7.2. Implement the contracted narrow write-unit operations and exercise rollback after each write, concurrent version and uniqueness races, failed SQL/commit, disconnect/reconciliation and warmed cache on both versions. Record actual worker exit codes and database state. Mark any unrun case NOT VERIFIED.

Prior findings D1-F-001–D1-F-006 remain open where these findings overlap; close them only after a new independent review. Preserve all prior reports and logs. Persistent-cache compatibility, PHP 8.1 and G-08 full product performance remain NOT VERIFIED.
