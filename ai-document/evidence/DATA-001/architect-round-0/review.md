## Findings and correction blueprint — revision 3, readiness PASS

**D1-F-001 / P1 / AC1, AC4 — Unauthorized snapshots from `query()`.** `RecordRepository.php:121-124,222-235` checks only the schema capability and returns every decoded envelope, including fields and audit, without `AccessPolicy::authorize()` for each object. `get()` applies an object policy, so the list path bypasses it. The schema offers no context builder and `authorize_read()` lacks the required service `vehicle_visible` context. Add trusted per-object context construction and the applicable read/action policy to every read path; reject unauthorized records before exposing fields, audit or counts. Add negative tests for technician/customer-contact and service visibility cases.

**D1-F-002 / P1 / AC2, AC4 — Transaction prerequisites and failure states are not enforced.** `WriteCoordinator.php:85-115` accepts zero or fewer than three table-engine rows as success and never rejects a pre-existing transaction. `run()` at lines 186-255 pins `$wpdb->dbh` before `ensure_lock_row()` (which may reconnect), ignores failures of timeout setup, START, ROLLBACK and timeout restoration, and classifies all lock-query failures as retryable conflicts. An unexpected exception after a lost connection is returned as `storage_unavailable`, although the commit state can be uncertain. Verify all three exact table names/engines, transaction state and connection identity before mutation; pin after initialization; check every control statement and rollback outcome; return `indeterminate` for uncertain state. Prove the outcomes with real fault injection.

**D1-F-003 / P1 / AC1, AC2 — Schema uniqueness and projection integrity are placeholders.** `RecordRepository.php:708-732` never queries registered unique keys. Projection writes at lines 901-939 neither reject duplicates nor check UPDATE errors; they can insert another row when a matching row is unchanged. `verify_write()` at lines 995-1025 checks only post and authoritative-meta counts, not payload, projection values or request marker. Implement and verify registered uniqueness and exact projection cardinality/value checks under the lock, including failed-statement rollback. Reject inconsistent pre-existing rows.

**D1-F-004 / P1 / AC1, AC2 — Idempotency marker does not bind the request to a type or actor.** `RecordRepository.php:654-695` compares only a fields fingerprint even though the stored marker includes type. Reusing one request ID with the same fields for another registered type returns the first type's snapshot. Validate type, fingerprint and created post type/status on replay, and reconcile ambiguous create/save outcomes under a fresh lock as required by the contract. Add cross-type and corrupt-marker negative tests.

**D1-F-005 / P1 / AC1–AC4 — Required real verification is missing or mislabeled.** `v2_concurrency.php` says its concurrency is simulated and cites the pre-implementation spike; it does not run two simultaneous repository workers, a same-unique-key race or multi-record rollback. `v4_cache_failure.php` tests a normal create and cites the spike for timeout, disconnect and rollback; it does not inject those failures into this code. `v3_retention.php` directly includes `uninstall.php` and resets the schema in one process, rather than exercising uninstall/reinstall. `v5_benchmark.php` does not check create results; run logs show its process completed in about one second, so the claimed 28,000-record generator was not demonstrated. Add actual disposable, isolated controls on both pinned WP versions with raw per-case output, database state and cleanup evidence. Label unrun cases NOT VERIFIED; do not count a reference to a prior spike as a passing application test.

**D1-F-006 / P2 / AC1, AC4 — Production schema registration is absent.** No `RecordSchema::register()` or `seal()` call appears in `src/Core/Plugin.php`; fixtures register ad hoc schemas themselves. The actual plugin therefore has no usable repository schema. Wire only approved, generic trusted definitions without inventing entity-specific validation; if the contract cannot be met before domain tasks, return an architectural gap rather than claiming application readiness. Verify the real bootstrap path on both WordPress versions.
