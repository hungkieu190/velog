## D1-F-021 approval and binding constraints

The proposal selects the approved safety architecture: direct `proc_open()` child with retained handle, Linux `/proc` PID/start ticks/executable/argv identity, PID-file agreement for verification only, socket-based shutdown, and deletion only after child-exit proof. Builder may now implement `run.php` and execute its isolated controls. The following details are binding, not optional follow-up design choices:

1. Launch with an argv array and retain the direct child handle. Capture `/proc/<pid>/stat` field 22 correctly despite parentheses in `comm`; compare a resolved `/proc/<pid>/exe` to the resolved executable chosen before launch; split `/proc/<pid>/cmdline` on NUL and require exact argument tokens for the unique datadir, socket and pid-file. Any unreadable/missing/mismatched identity or PID file fails closed.
2. Never call blocking `proc_close()` while the child may still run. Poll the retained handle for a bounded interval, then call `proc_close()` only after exit is observed. Check and report its result. The `mysqladmin` command itself needs an outer wall-clock timeout as well as a connect timeout, and must target only this run's socket.
3. No PID-directed `posix_kill()`, `proc_terminate()` or process-group signal, including early setup failures. Attempt bounded socket shutdown whenever the socket is available. If child exit cannot be proved, return nonzero, preserve the run-owned directory, report the live identity/path, and do not delete or claim full cleanup. A failed test remains failed even if a later recovery shutdown succeeds.
4. Removal uses only the exact generated directory path, checks remover exit and path absence. `--keep-tmp` preserves the path intentionally and returns zero only if tests and shutdown passed. Inject deletion failure with a deterministic failing remover stub and assert that the stub was invoked. No `chmod` failure control.
5. Add executable controls for identity/PID-file failure, shutdown timeout/error, child-exit uncertainty, deletion failure and an unrelated sentinel. Each must assert exit code, process/path state and expected diagnostic marker. Use bounded, owned mock children or recovery shutdown so negative controls do not leave unreported live resources. Record every owned temporary path/process and cleanup outcome.

These constraints are within the approved proposal and round-7 blueprint; no new proposal round is required. If a concrete platform contradiction prevents them, report that contradiction before substituting another mechanism.
