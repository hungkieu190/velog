# D1-F-021 Proposal Revision 5: Bounded Owned-Process Cleanup

This proposal maps the Architect's cleanup blueprint to `run.php`.

## 1. Process Launch and Identity Capture

- **Direct Child Execution:** Launch MariaDB (`mariadbd` or `mysqld`) directly using `proc_open()` with a strict `$argv` array (no shell wrapper). The returned resource handle is retained.
- **Identity Capture:** Immediately obtain the child's process ID (PID) from `proc_get_status()`.
- **Absolute Identity:** Read `/proc/<pid>/stat` field 22 (start time in jiffies) and combine it with the PID to form a unique, unforgeable process identity (`pid:start_ticks`).

## 2. Process and Argument Validation

- **Executable Verification:** Resolve the symlink `/proc/<pid>/exe` and assert it points exactly to the expected MariaDB executable (e.g., `mariadbd` or `mysqld`).
- **Exact Argument Matching:** Read `/proc/<pid>/cmdline` (which is NUL-delimited). Assert that the exact `--datadir`, `--socket`, and `--pid-file` arguments match the unique, run-owned temporary paths generated by `run.php`.
- **PID-File Agreement:** Read the created `.pid` file from the temporary directory and assert it contains exactly the same PID as the `proc_open()` child. **Note:** The PID file is used only for verification, never as the source of a signal.

## 3. Shutdown and Validation

- **Bounded Socket Shutdown:** Initiate graceful shutdown via the run-owned Unix socket using `mysqladmin --socket=... --connect-timeout=5 shutdown`.
- **Child Exit Proof:** After sending the shutdown command, block on `proc_close()` (or loop polling `proc_get_status()`) with a maximum wait time. Prove that the child process exited by verifying `proc_get_status()['running'] === false` on the retained handle.
- **Cleanup Deletion:** Only after proving the child has fully exited, delete the exact run-owned temporary directory recursively.

## 4. Failure and Diagnostic Retention

- **Uncertain Shutdown:** If the child process does not exit within the timeout, or if shutdown fails, the script will **fail**.
- **Diagnostic Retention:** On any failure (early exit or uncertain shutdown), or if `--keep-tmp` is provided, the temporary directory is intentionally preserved (not deleted).
- **Live Process Reporting:** On uncertain shutdown, output the live, owned process identity (`pid:start_ticks`) and temporary path to stderr for diagnostic purposes.
- **No Rogue Signals:** `kill` (SIGKILL/SIGTERM) is never issued to a PID read from a file or to the retained handle; shutdown relies exclusively on `mysqladmin` via the owned socket.

## 5. Deterministic Negative Controls

- **Deletion Negative Control:** Instead of relying on unreliable `chmod` hacks, the deletion failure control will substitute a deterministic failing remover stub (e.g., overriding the remover command with `/bin/false` or throwing an exception in the PHP removal function) to prove that deletion failures are correctly caught and reported.

## 6. Exact Verification Oracles

For every early and cleanup failure, `run.php` will define exact oracles:
- **Exit Code Oracle:** Must exit `1` on any failure.
- **Process Oracle:** The owned process identity (`pid:start_ticks`) must be recorded; if uncertain shutdown occurs, it must be reported live.
- **Path Oracle:** The exact temporary directory path must be retained (not deleted) and its location outputted.
- **Sentinel Oracle:** The script will output explicit sentinel markers (e.g., `ERROR: Socket shutdown timed out`, `ERROR: Directory removal failed`) for test assertions to parse.

**Implementation Gate:** `run.php` will not be edited or executed until the Architect explicitly records `APPROVED FOR IMPLEMENTATION`.
