## Blocking findings

1. **D1-F-019 / P1 / D1-F-015 still open — save reconciliation can falsely confirm a different write.** `RecordRepository.php:1760-1780` validates `$canonical_changes` but never passes it into the reconciliation callback. Lines 1812-1837 accept any audit entry with the request hash, actor and `save` operation. They do not validate the expected version position, canonical before/after values, or a gap-free version sequence. A reused request ID with different changes or expected version can be reported as committed. Implement the exact proposal review 5 constraint 3; add negative cases for altered changes, version, malformed audit entries and gaps on both disposable versions.
2. **D1-F-020 / P1 / D1-F-013 still open — query SQL errors become successful empty results.** `RecordRepository.php:189` casts a failed count query to zero; lines 239-246 return an empty page when the page SQL returns `false`; lines 254-264 treat a failed duplicate preflight as no duplicates. Return `storage_unavailable` for every failed SQL read before inferring count, page emptiness or integrity. Add executable failure controls for each read.
3. **D1-F-021 / P1 / D1-F-017 still open — cleanup is not ownership-safe and failure does not fail the suite.** `tests/fixtures/wp-integration/data001/run.php:390-416` reads a PID file and signals that number without checking recorded process identity/start time; PID reuse can target another process. SIGTERM/SIGKILL results, post-KILL absence, and `rm -rf` exit/absence are not checked. `overall_exit` stays zero and cleanup is logged complete even if it fails. Use a recorded child identity and exact owned directory, check each exit/absence, and force a nonzero suite result on cleanup failure. Do not rerun this runner until fixed. This is the second consecutive failed implementation review for this underlying defect and requires the repeated-finding approach gate.
4. **D1-F-022 / P1 / D1-F-015 still open — create reconciliation does not prove committed projection integrity.** `RecordRepository.php:1690-1719` checks the post row and decodes the envelope, then returns a snapshot without checking the required state/visibility projection rows, exact cardinality or equality against the envelope. A corrupted committed candidate can be returned as valid. Reuse the bounded pinned-handle integrity check, including marker shape and candidate identity, before reporting success; add corruption controls.
5. **D1-F-023 / P1 / D1-F-016 still open — required V4 controls are absent.** `v4_cache_failure.php` and both raw logs exercise a pre-commit disconnect and ordinary committed create/save reconciliation; no `post_commit_lost_ack` fault is hit. Live-handle COMMIT failure and coordinator 1213 are explicitly NOT VERIFIED, so V4 and the full DATA-001 matrix cannot be called passed. Preserve those labels, implement the safe executable controls from the approved scope where possible, and report any remaining architectural gap without a passing claim. The missing V3 regional/term retention controls from D1-F-016 also remain to be evidenced.
