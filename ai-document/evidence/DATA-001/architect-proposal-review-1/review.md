## Required corrections before implementation approval

1. **D1-F-013 — bounded authorized pagination:** A SQL `LIMIT/OFFSET` over all posts before object-policy evaluation cannot produce complete authorized pages or an exact authorized total. The proposed indexed SQL count also cannot reproduce `AccessPolicy` decisions that depend on values inside the serialized envelope. Specify a concrete bounded keyset/candidate scan, where and how policy runs, how the exact authorized count is derived without loading every audit blob into PHP, and how malformed or duplicate authoritative rows fail closed. Include mixed-visibility page 1/page 2 and nontrivial-scale controls. If this cannot be done under the current storage map and API, identify the precise architectural gap rather than promising an unsupported two-tier count.
2. **D1-F-014 — composite uniqueness:** `GROUP BY post_id HAVING COUNT(*) = N` is insufficient when a projection key has duplicate rows or a tuple has repeated/missing keys. Spell out the allowlisted, parameterized complete-tuple predicate, post type/status binding, per-key exact cardinality and value checks, current-ID exclusion, and behavior on every SQL failure. Distinct `(A,B)` tuples sharing A must remain valid; exact collisions must fail.
3. **D1-F-015 — indeterminate reconciliation:** Define separate create and save reconciliation against request ID, expected type/ID/version, actor policy, full authoritative envelope and idempotency/audit marker. A missing create marker after a lost acknowledgement is not automatically proof that a retry is safe until the new lock and authoritative checks establish it. State exact result/error codes for committed, definitely uncommitted and still-uncertain outcomes. Return `indeterminate` if rollback fails even after 1205/1213. Define cache invalidation and timeout-restoration failure handling without treating a normal cache miss as a failed invalidation.
4. **D1-F-016 — failure controls:** Map tests to actual fault points and expected database state for failure after each write, SQL failure, deadlock, lost COMMIT acknowledgement, disconnect before/after COMMIT and reconciliation. Explain how each control proves the intended path on both WordPress versions using the pinned handle; do not label a skipped case PASS.
5. **D1-F-017 — process ownership:** Use atomic unique-directory creation, record PID and process start identity, verify identity before TERM/KILL, reap only the owned daemon, confirm its absence, and only then remove the owned directory. A random suffix or PID alone is insufficient. Check shutdown/removal command results; any failure makes the suite nonzero. No `pkill -f`.
6. **D1-F-018 — schema policy contract:** `RecordSchema::register()` currently returns `void` and throws on invalid definitions; the proposal's `WP_Error` return changes that API. Keep the pinned API or explicitly justify a compatible adjustment. Specify when trusted domain definitions are registered relative to `register_core_schemas()` sealing, and how every new field gets an exposure class before use. Explain how customer audit before/after projections use that class. Do not add entity-specific fields in DATA-001.
