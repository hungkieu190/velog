## Finding disposition

- **CORE4-F-001 — code changed, verification open:** `ShopSettings::save_settings()` now uses a conditional SQL update tied to serialized prior value and checks affected rows. This is closer to an atomic CAS than round 1. The fixture calls the handler twice sequentially using an old version; it does not create competing writers or prove one winner and one unchanged loser. Stored envelope normalization can differ from the exact serialized DB value. Require a real two-writer test, an exact stored-value comparison contract, and cache consistency proof before closure.
- **CORE4-F-002 — OPEN, second consecutive failure:** `ShopSettings::get_settings()` casts arbitrary stored `record_version` and `currency_scale`, defaults invalid schema/catalog version, and treats any nonempty `configured` value as true. `require_configured()` checks currency existence but does not check its catalog-derived scale or schema. `save_settings()` still casts array/object `distance_unit` and `currency_code` to string before validation, which can emit warnings. `RegionalSettingsPage::handle_save()` casts malformed `record_version` (including arrays) to an integer and passes an unchecked nonce value to string functions. Invalid/corrupt data may be presented as configured or cause an uncaught type error. Fix before further implementation review.
- **CORE4-F-003 — code changed, verification open:** `Assets::enqueue_styles()` now uses an exact hook list and `assets/css/admin.css`. Confirm the generated URL resolves to the actual file in isolated WordPress and that unrelated admin pages receive no VeLog asset. No such evidence was supplied.
- **CORE4-F-004 — OPEN, second consecutive failure:** The fixture invokes `RegionalSettingsPage::handle_save()` for denied actors, but the stale case is sequential and checks only a notice. It does not assert unchanged storage after denial or exercise simultaneous writers. The “historical record” is a direct `postmeta` insert with a non-repository envelope; it does not prove DATA-001 record identity or canonical distance through `RecordRepository`. Locale, uninstall/reinstall retention, and JPY/USD/KWD coverage are absent.
- **CORE4-F-005 — OPEN, second consecutive failure:** Independent `composer run lint` exits 1 at PHPCS (warnings in Admin, ShopSettings and custom capability configuration); PHPStan is not reached. `git diff --check --cached` exits 2 with CORE-004 whitespace among other staged files. Builder report claims lint success but provides no log. Required architecture/internationalization updates and manual keyboard/320px/RTL/long-string walkthrough remain absent. Checklist and task report/prompt are stale.
- **CORE4-F-006 — OPEN, first implementation review failure:** `AdminMenu::add_menu_pages()` requires `mf_velog_manage_records` for the top-level VeLog menu, but `Capabilities::$role_caps` grants no such capability to administrator, manager or technician.
